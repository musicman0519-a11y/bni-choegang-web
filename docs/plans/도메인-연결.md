# 도메인 연결 작업 계획   (도메인: choegang.co.kr, 2026-11-18 합의)

목표: https://choegang.co.kr 에서 사이트가 HTTPS 로 열리고, www.choegang.co.kr 은 choegang.co.kr 로 넘어가며, 모든 정본 주소(canonical·사이트맵·llms.txt)가 새 도메인으로 바뀐다.

## 설계 결정
- 정본은 **choegang.co.kr(루트)**, www 는 리다이렉트. GitHub Pages 는 CNAME 파일에 적힌 쪽을 정본으로 쓰고 다른 쪽을 301 로 보낸다.
- **순서가 중요**: DNS 를 먼저 등록기관에서 넣고 전파를 확인한 뒤에 저장소에 CNAME 파일을 넣는다. 반대로 하면 CNAME 을 넣는 순간 github.io 주소가 아직 안 풀리는 도메인으로 리다이렉트돼 사이트가 잠시 안 열린다.
- 하위 경로(`/bni-choegang-web/`)에서 루트(`/`)로 바뀌지만 사이트가 전부 상대경로라 코드 수정은 없고, `site.config.json` 의 `origin` 만 바꿔 `npm run build` 로 재생성한다. 404.html 은 두 경로를 모두 처리하도록 이미 돼 있다.

## 위험 요소
- 도메인이 아직 구매 전이거나 DNS 가 비어 있으면(2026-11-18 조회 시 A·NS 응답 없음) 1번부터 막힘. 등록기관과 구매 여부 확인 필요.
- `.co.kr` 은 등록기관 DNS 전파가 10분~수 시간. 전파 전에 CNAME 파일을 넣지 않는다.
- Enforce HTTPS 는 인증서 발급 전에는 체크할 수 없다. "Certificate pending" 이면 기다린다.
- 옛 github.io 주소로 이미 공유된 링크는 GitHub 가 새 도메인으로 301 해 주므로 깨지지 않는다.
