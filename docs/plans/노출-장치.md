# 노출 장치(SEO·AEO·GEO) 작업 계획   (명세: 없음 — 2026-11-18 합의: "우리 홈페이지를 쓰되 옛 사이트의 노출 장치를 이식")

목표: 새 사이트가 검색엔진과 AI 크롤러에 **JS 없이도** 읽히게 한다. 페이지별 메타·canonical·OG, robots·사이트맵·llms.txt, 구조화 데이터, 그리고 글·멤버마다 **정적 HTML 페이지**를 생성한다.
도메인은 아직 없으므로 사이트 주소는 한 곳(`site.config.json`)에만 두고, 도메인이 생기면 그 값만 바꿔 다시 생성한다.

## 설계 결정
- **정적 생성 방식.** GitHub Pages 에는 서버가 없으므로 `node tools/build/prerender.js` 가 `blog-data.js`·`blog-legacy.js`·`experts.js` 를 읽어 `blog/<글id>/index.html`, `member/<이름>/index.html`, `sitemap.xml`, `llms.txt` 를 만든다. 생성물은 커밋한다(배포가 곧 파일이므로).
- 생성된 글 페이지는 `post.html` 을 템플릿으로 쓰고 `<article>` 안에 본문을 미리 채운다. `<base href="../../">` 로 상대경로를 유지한다(CLAUDE.md 규칙). 페이지 안에 `window.postId` 를 심어 `blog.js` 가 `?id=` 없이도 같은 글을 그린다.
- 글의 정본 주소는 `blog/<id>/`. 목록 카드와 홈 뉴스 타일도 이 주소로 링크하고, `post.html?id=` 는 남겨 두되 canonical 을 `blog/<id>/` 로 가리킨다. 옛 사이트 주소 체계와 같아져서 나중에 옛 도메인을 넘겨받아도 그대로 맞는다.
- 구조화 데이터는 정적 HTML 에 직접 넣는다(옛 사이트처럼 JS 주입이면 AI 크롤러가 못 봄). 홈: Organization+WebSite+FAQPage, 참관: Event(매주 수요일 06:30~08:30, 킨텍스로 255-3), 글: BlogPosting+Breadcrumb, 멤버: Person+LocalBusiness/ProfessionalService.
- 과장 표현 필터(최고·유일·완치·100% 보장 등)는 생성기에서 메타·스키마 문구에만 적용한다. 본문은 건드리지 않는다.
- llms.txt 는 옛 사이트 것을 바탕으로 하되 수치 주장(TYFCB 9억 등)은 빼고, 멤버 디렉터리는 `experts.js` 에서 자동 생성한다.

## 위험 요소
- `<base href>` 는 페이지 안 모든 상대 링크에 영향. 앵커(`#id`)와 `?id=` 링크가 base 기준으로 바뀌므로 7번에서 글 페이지의 모든 링크를 눌러 확인.
- 정적 글 페이지와 `post.html?id=` 두 주소가 공존 → canonical 로 정본을 지정하면 중복 색인은 안 됨.
- Supabase 연결 후 관리자가 새 글을 쓰면 정적 페이지는 **빌드를 다시 돌려 커밋해야** 생긴다. 그 전까지는 `post.html?id=` 로만 열림(JS 렌더). 자동화(GitHub Actions 가 DB 를 읽어 빌드)는 다음 계획.
- 멤버 페이지는 개인 정보(이름·회사·사진·명함)를 검색에 노출. 옛 사이트에서도 공개돼 있던 범위로 한정하고 전화번호는 명함 이미지 안에만.
- Pages 하위 경로(`/bni-choegang-web/`)와 도메인 루트는 절대 URL 이 다름 → `site.config.json` 하나로 관리, 도메인 전환 시 재생성 1회.
- 의료·법률 멤버 문구는 소개 목적만. 진료 효과·승소 주장은 생성기 필터로 메타에서 차단.

## 발견 사항
- 404.html 은 그대로 둠: 없는 `blog/<id>/` 로 들어오면 `post.html?id=` 로 보내 "글을 찾을 수 없습니다"를 띄우므로 무한 리다이렉트가 없고, 존재하는 글은 404 를 타지 않음.
- 멤버 페이지의 활동지역은 일괄 "고양·일산·파주·김포". 멤버별 실제 권역(옛 DB region)은 다음 단계에서 experts.js 에 `region` 필드로 넣으면 생성기가 그대로 씀.
- 관리자가 DB 에 새 글을 쓰면 정적 페이지는 `npm run build` 전까지 없음. GitHub Actions 로 자동 빌드하는 건 Supabase 연결 뒤 별도 작업.
