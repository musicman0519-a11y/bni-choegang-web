# 옛 콘텐츠 이관 작업 계획   (명세: 없음 — 2026-11-18 대화에서 합의)

목표: 옛 홈페이지 패키지(bni_clean.zip)의 멤버 소개 카드·멤버 링크·블로그 글을 새 사이트에 올려
GitHub Pages 공개 URL 에서 바로 보이게 한다. Supabase 연결 전이므로 **정적 파일에 먼저** 넣고,
나중에 관리자 "기존 글 가져오기" 버튼으로 DB 에 그대로 들어가게 한다.

## 설계 결정
- 글은 `blog-data.js` 를 건드리지 않고 **`blog-legacy.js`(새 파일)** 로 분리해 `window.staticPosts` 에 덧붙인다. 손으로 쓰는 글과 자동 변환 글을 섞지 않기 위해서다. 53건 본문을 넣으면 200KB 안팎이라 별도 파일이 맞다.
- 옛 글 본문은 **HTML 로 변환**해 `body` 에 넣는다. 새 사이트 정적 글은 HTML body 를 그대로 렌더하고, DB 로 가져갈 때는 관리자가 이미 `htmlToText`(H2→`##`, 나머지 문단)로 바꿔 주므로 추가 코드가 필요 없다.
- 글 id = 옛 slug (예: `weekly-meeting-20260513`). 나중에 `/blog/슬러그` 옛 주소 호환에 그대로 쓴다.
- 새 사이트 멤버소개 글 8건과 겹치는 옛 글 8건은 **새 글을 유지하고 옛 본문만 채워 넣는다**(새 글 7건은 본문이 비어 "준비 중"으로 표시되는 상태).
- 변환 스크립트는 `tools/import-legacy/`(저장소 안, 재실행 가능)에 두고, 입력 덤프 파일은 저장소 밖 `E:\projects\_backup\bni_clean\` 에서 읽는다(전화번호 등 원본 데이터는 커밋하지 않음).
- 명함 이미지는 원본 2298×3250 이 너무 커서 **긴 변 1600px, JPEG 품질 82** 로 줄여 넣는다.
- 전화번호·SNS·활동지역은 새 사이트 UI 에 표시 자리가 없어 이번 범위에서 **보류**. 명함 이미지에 이미 전화번호가 들어 있다. 플레이스/홈페이지 링크(`homepage`)만 반영한다.

## 위험 요소
- 사진 160장 소실: 주간회의 10건·행사 8건은 글이 텍스트만 남아 밋밋함. 멤버 단톡방 사진으로 나중에 채우는 건 별도 작업.
- 옛 HTML 글은 작성 도구가 만든 인라인 스타일이 많아 태그를 벗기면 강조·구분선이 사라질 수 있음. 7번 확인에서 5건 눈으로 보고 규칙을 조정.
- 글 작성자 표기: 옛 글은 대부분 "BNI 관리자". 멤버 글은 member 연결로 충분하고 작성자는 표시하지 않음.
- `blog-legacy.js` 추가로 블로그 페이지 첫 로딩이 200KB 늘어남. 목록은 제목·요약만 쓰므로 체감은 작지만, 느리면 본문을 글별 JSON 으로 쪼개는 후속 작업.
- 겹치는 8건 병합 때 새 글의 `profile`(전문분야·핵심역량·활동지역)은 유지하고 본문만 바꾼다. 옛 본문 안의 "BNI 최강챕터 공인…" 같은 머리글은 새 상세 페이지가 이미 보여 주므로 중복 제거 필요.
- 명함 카드에 개인 전화번호가 들어 있음. 옛 사이트에서도 공개돼 있던 정보지만 3번에서 사용자가 한 번 확인.
- Supabase 연결 뒤 "기존 글 가져오기"는 `posts.body` 에 텍스트로 저장되므로 h3·목록은 평문이 됨. 서식을 지키려면 그때 `site-data.js` 의 `bodyText` 를 HTML 허용으로 바꾸는 한 줄 수정이 필요(배포-준비 10번에서 결정).
