## 설계 결정
- 호스팅: **GitHub Pages** (추천). 이유: 저장소와 같은 계정, 무료, 추후 도메인 연결 쉬움, 사이트가 전부 상대경로라 `/저장소명/` 하위 경로에서도 깨지지 않음.
  대안: Netlify (드래그앤드롭 배포, 리다이렉트/폼 기능) — GitHub Pages 가 불편하면 교체. 코드 변경 없이 전환 가능.
- Supabase anon 키는 공개 키이므로 `supabase-config.js` 에 넣어 **커밋한다**. service_role 키·Edge Function 비밀값은 절대 커밋하지 않는다.
- 14MB zip 백업은 저장소에 넣지 않는다(프로젝트 밖으로 이동 + .gitignore).

## 위험 요소
- gh CLI 미설치: 2·3번은 웹/GitHub Desktop 으로 진행하거나 `winget install GitHub.cli` 후 `gh auth login`. 필요하면 1번에서 함께 설치.
- GitHub Pages 는 Public 저장소만 무료. 멤버 사진·명함 이미지가 저장소에 공개됨(이미 홈페이지에 공개되는 자료라 문제 없다고 판단, 확인 필요).
- Supabase 무료 플랜은 7일간 요청이 없으면 프로젝트가 일시정지됨 → 관리자가 주 1회 접속하거나 Pro 전환. 도메인 연결 단계에서 다시 검토.
- 이메일 확인 링크가 Pages 주소로 돌아오므로 7번(Redirect URLs)을 빼먹으면 9번에서 "invalid redirect" 로 막힘.
- 도메인 연결 후에는 7·14번의 URL 을 새 도메인으로 바꿔야 함 — 다음 계획에 포함.
- 캐시 버스팅이 `?v=숫자` 수동 방식이라 재배포 후 구버전이 보일 수 있음 → 강력 새로고침으로 확인.

## 발견 사항
