# 보안 강화 작업 계획   (2026-11-22 점검 기준)

## 현재 상태 (이미 잘 된 것)
- DB: 표 6개 전부 RLS 켜짐. 쓰기는 `is_admin()`(admins 표에 등록된 이메일)만, 읽기는 공개 데이터만. 문의는 익명 INSERT 만 허용(status='new', memo 없음 강제).
- 가입: `auth.users` 트리거가 admins 표에 없는 이메일의 계정 생성을 거부. 관리자 비밀번호는 Supabase 가 해시 저장.
- 저장소(media): 읽기 공개, 쓰기·수정·삭제는 관리자만.
- 키: 사이트에 노출된 키는 publishable(공개용)뿐. secret 키는 어디에도 없음. GitHub secret scanning 켜짐.
- 관리자 페이지: 메뉴에 링크 없음, noindex, robots 차단.

## 설계 결정
- 호스팅이 GitHub Pages 라 HTTP 응답 헤더(HSTS·CSP 등)는 못 만진다. CSP 는 `<meta http-equiv>` 로 넣는다(헤더보다 약하지만 XSS 2차 피해를 줄임). HSTS 는 GitHub 이 HTTPS 강제 리다이렉트로 대체.
- 스팸 방지는 비용 0인 것부터: 허니팟 + 제출 간격 + DB 트리거(같은 전화번호 1시간 3건 제한). 그래도 스팸이 오면 Cloudflare Turnstile(무료) + Edge Function 검증을 2단계로.
- 관리자 2단계 인증(TOTP)은 Supabase 가 지원하므로 admin.js 에 등록·확인 흐름을 붙인다. 관리자 2~3명뿐이라 "필수"로 둔다.
- 외부 스크립트(supabase-js CDN)는 버전 고정 + SRI 해시로 변조를 막는다.

## 위험 요소
- CSP 메타는 `unsafe-inline` 스타일을 허용해야 기존 인라인 스타일이 깨지지 않음. 스크립트는 인라인이 없으므로 엄격하게 둘 수 있음(정적 글 페이지의 `window.postId` 인라인 1줄은 nonce 없이 안 되므로 data 속성으로 바꿔야 함 → 5번에 포함).
- TOTP 를 필수로 하면 인증 앱을 잃어버린 관리자는 로그인 불가 → Supabase 대시보드에서 MFA factor 삭제로 복구(15번 문서에 포함).
- DB 트리거 제한은 정상 신청자도 1시간 3건에 걸릴 수 있음(가족 대신 신청 등). 거부 메시지를 친절하게("잠시 후 다시 시도").
- 백업 워크플로가 secret 키를 쓰면 유출 시 피해가 큼. GitHub Secrets + 최소 권한(읽기 전용 role 생성)으로 제한하거나 inquiries 백업은 생략.
- Turnstile 은 사이트 폼을 Edge Function 을 통해 제출하도록 구조를 바꿔야 해서 이번 범위에서 제외. 스팸이 실제로 오면 추가.
