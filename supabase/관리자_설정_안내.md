# 관리자 페이지 설정 안내

관리자 페이지 주소: `admin.html` (예: `https://내도메인/admin.html`)
메뉴에는 링크가 없으니 주소를 직접 입력해 들어갑니다.

## 1. Supabase 프로젝트 만들기 (처음 한 번)

1. https://supabase.com 에 가입 → **New project**
2. 프로젝트 이름: `bni-choegang`, 데이터베이스 비밀번호는 따로 적어 두기, Region: **Northeast Asia (Seoul)**
3. 프로젝트가 만들어질 때까지 1~2분 기다리기

## 2. 데이터베이스 만들기

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. `supabase/schema.sql` 파일 내용을 전부 붙여넣기
3. **맨 마지막 줄의 `admin@example.com` 을 관리자로 쓸 이메일로 바꾸기**
4. **Run** 클릭 → "Success" 가 나오면 완료

## 3. 관리자 계정 만들기

1. 홈페이지의 `admin.html` 에 들어가서 **'처음이신가요? 계정 만들기'** 클릭
2. 2번에서 적은 것과 **같은 이메일**과 비밀번호(8자 이상) 입력
3. 이메일로 온 확인 링크를 누른 뒤 로그인

> 관리자로 등록되지 않은 이메일은 계정 만들기가 데이터베이스에서 막혀요. 그래서 Supabase 의 **Allow new users to sign up** 설정은 **켜 둔 채로** 두세요.
> 확인 메일 없이 바로 쓰고 싶으면 **Authentication → Sign In / Providers → Email → Confirm email** 을 끄면 됩니다.

## 4. 홈페이지에 연결하기

1. 왼쪽 메뉴 **Project Settings → API** (또는 Data API)
2. **Project URL** 과 **anon public** 키를 복사
3. 홈페이지 폴더의 `supabase-config.js` 에 붙여넣기

```js
window.SUPABASE_URL = "https://xxxxxxxx.supabase.co";
window.SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

> `service_role` 키는 절대 넣지 마세요. anon 키는 공개돼도 괜찮은 키이고, 데이터는 2번의 보안 규칙으로 보호됩니다.

## 5. 기존 데이터 옮기기 (처음 한 번)

`admin.html` 에 로그인한 뒤

- **멤버** 탭 → **기존 멤버 가져오기** (지금 홈페이지의 30명)
- **블로그** 탭 → **기존 글 가져오기**
- **메인 배너** 탭 → **기본 사진 가져오기** (선택)

가져오기 전까지는 홈페이지가 기존 데이터를 그대로 보여 줍니다.

## 관리자 페이지에서 할 수 있는 일

| 탭 | 기능 |
|---|---|
| 문의 | 참관(비지터) 신청 · 협업 문의 확인, 처리 완료 표시, 메모, 삭제. 카드의 **유입 경로**를 펼치면 어디서(네이버·구글·인스타·직접) 와서 어떤 페이지를 거쳐 얼마나 머물다 신청했는지 보입니다. 운영진이 직접 테스트할 땐 주소 뒤에 `?journey=off` 를 한 번 붙이면 그 브라우저는 기록되지 않습니다 |
| 멤버 | 추가 · 수정 · 숨기기 · 삭제, 프로필 사진 · **명함 이미지** 올리기, **홈페이지 링크**, 등급(골드·그린) · 직급(의장 등), 순서 |
| 블로그 | 글 쓰기 · 수정 · 숨기기 · 삭제 |
| 메인 배너 | 사진 올리기, 순서 바꾸기, 숨기기, 삭제 |
| 일정 | 휴회 · 화상회의 · 행사 날짜 등록 (매주 수요일 조찬회의는 자동) |
| 관리자 계정 | 관리자 이메일 추가 · 삭제 (본인과 마지막 1명은 삭제 불가) |

## 관리자를 더 추가하려면

1. 관리자 페이지 → **관리자 계정** 탭 → 이메일 입력 → **관리자 추가**
2. 추가된 사람이 `admin.html` 에서 **'처음이신가요? 계정 만들기'** 로 같은 이메일 가입

관리자 권한을 삭제하면 그 사람은 로그인해도 관리자 기능을 쓸 수 없어요.

## 문의가 오면 메일·문자로 받기

`알림_설정_안내.md` 를 따라 설정하면 새 문의가 들어올 때 관리자에게 메일과 문자가 바로 갑니다.


## 보안 설정 (2026-11-22 기준으로 적용된 것)

- 관리자 로그인은 **비밀번호 + 인증 앱 6자리(2단계)** 입니다. 2단계를 거치지 않은 세션은 DB 를 고칠 수 없습니다.
- 로그인 5회 실패 시 60초 잠금, 로그인 12시간 뒤 자동 로그아웃, 새 비밀번호는 10자 이상.
- 문의 폼: 숨은 필드(허니팟)·제출 간격·같은 번호 1시간 3건 제한. 처리 완료 문의는 90일, 미처리 문의는 1년 뒤 자동 삭제(`purge-old-inquiries` 예약).
- 주간 백업: GitHub Actions "DB backup" 이 매주 월요일 멤버·글·배너·일정을 JSON 으로 저장(Actions → 실행 → Artifacts, 90일 보관). 문의는 개인정보라 백업에 넣지 않습니다.

## 문제가 생겼을 때 (복구 절차)

| 상황 | 할 일 |
|---|---|
| **관리자 비밀번호를 잊음** | Supabase → Authentication → Users → 해당 계정 ⋯ → **Send password recovery** → 메일의 링크로 재설정. 또는 다른 관리자가 Users 에서 계정을 지우고 본인이 admin.html 에서 다시 "계정 만들기" |
| **인증 앱(휴대폰)을 잃어버림** | Supabase → Authentication → Users → 해당 계정 클릭 → **Multi-factor** 영역의 factor 삭제 → 다음 로그인 때 QR 등록부터 다시 |
| **공개 키(publishable)가 유출된 것 같음** | 공개 키는 원래 공개용이라 유출 자체는 문제가 아닙니다. 그래도 바꾸려면 Settings → API Keys → **New publishable key** 생성 → `supabase-config.js` 의 키 교체 → `npm run build` → 커밋·푸시 → 옛 키 삭제 |
| **secret 키가 유출됨** (이 사이트는 쓰지 않음) | Settings → API Keys → 해당 secret key **Delete** 후 새로 발급. 어디에도 넣지 않았으므로 사이트 영향 없음 |
| **프로젝트가 일시정지(Paused)** | 대시보드에서 **Restore project**. 무료 플랜은 7일간 요청이 없으면 멈추는데, GitHub Actions "Supabase keepalive" 가 주 2회 깨웁니다 |
| **표를 잘못 지움 / 데이터 복구** | GitHub → Actions → **DB backup** → 가장 최근 실행 → Artifacts 의 JSON 내려받기 → Supabase Table Editor 의 **Insert → Import data from CSV** (JSON 을 CSV 로 바꿔서) 또는 SQL Editor 에서 insert |
| **스키마를 처음부터 다시** | SQL Editor 에서 `supabase/schema.sql` 전체 실행(멱등) → `supabase/migrations/*.sql` 순서대로 실행 |
| **스팸 문의가 몰림** | 자동 제한이 걸려 있지만 그래도 많으면 관리자 문의 탭에서 삭제. 계속되면 Cloudflare Turnstile 도입(개발 필요) |
| **사이트가 안 열림** | GitHub → 저장소 → Settings → Pages 에서 상태 확인, 가비아 DNS 레코드(A 4개·CNAME www) 확인 |
